## §B: 性能与并发控制协议

> 本协议自包含，不依赖其他章节即可执行。
> 概念关系见 `../references/knowledge-graph.md` §支线B。
> 动态控制病深度展开 → `dynamic-control-diseases.md`

---

### 1. 问题信号

以下任一信号出现，优先按本协议处理：

- 循环内发 RPC 或数据库调用
- 查询无条件分页或 LIMIT 过大
- N+1 查询模式（1 次列表查询后逐条展开）
- 大对象一次性加载进内存（全量读表 / 大文件一次性反序列化）
- 无索引意识（WHERE 字段无索引、JOIN 大表）
- 普通 HashMap / ArrayList 用于多线程环境
- 全方法 `synchronized` 或等效全局锁
- 重试无退避策略（固定间隔连打）
- 异步任务无并发限制（队列无界、线程池无上限）
- 缓存引入后缺少失效策略或一致性说明

---

### 2. 观测基线协议：无观测，不优化

在改动任何实现之前，必须先拿到观测基线。禁止凭感觉优化。

**最小入场券（至少满足 2 项）：**

| 观测手段 | 拿到什么 | 典型工具/命令 |
|----------|----------|--------------|
| trace | 跨服务调用链中卡在哪一跳 | Jaeger / Zipkin / 链路追踪 |
| flame graph | CPU / wall time 烧在哪个函数 | perf / pprof / async-profiler |
| profiling baseline | 修改前的性能剖面 | `cargo bench` / `wrk` / `ab` |
| golden signals | 延迟(P50/P99) / 流量(QPS) / 错误率 / 饱和度 | Prometheus / Grafana |
| slow query | 慢 SQL 与执行计划 | `EXPLAIN ANALYZE` / slow query log |
| A/B 或对照 | 修改前后可比较 | canary / shadow / 压测对照 |

**执行规则：**
1. 无观测基线，禁止开始优化。
2. 观测不足时，先补观测点或 profiling，再决定是否改代码。
3. "感觉这里慢"不能直接升级为优化动作。
4. 优化结果必须和修改前的 profiling baseline 做一次对照。

---

### 3. 控制输入 → 输出影响矩阵

每个优化动作都是控制输入，会连带影响多个输出。改动前先写出影响方向。

| 控制输入 (knob) | 目标输出 (+) | 连带输出 (-) | 高耦合？ |
|-----------------|-------------|-------------|----------|
| 加缓存 | 降低 DB 压力 | 一致性风险、过期策略复杂度、缓存击穿风险 | **是** |
| 加重试 | 提高短期成功率 | 尾延迟变高、下游 QPS 放大、队列积压 | **是** |
| 改异步 | 主链路变短 | 最终一致性、补偿开销、对账复杂度 | **是** |
| 加锁 | 保护临界区 | 吞吐下降、死锁风险、锁竞争 | **是** |
| 引入连接池 | 复用连接降低开销 | 连接泄漏、池满阻塞、配置漂移 | 中 |
| 调大 batch size | 提高吞吐 | 延迟上升、内存占用增大 | 中 |
| 调高并发度 | 提高吞吐 | CPU/IO 竞争、排队时延上升 | **是** |

**高耦合 knob 的处置规则：**
- 一次只调一个 knob，不做组合调整。
- 小步试探（调 20% 而不是直接翻倍），先验证方向再调量。
- 改动后冷却一个观测窗口，再评估是否继续。

### 4. 并发归属检查

涉及共享状态时，逐项自检：

1. **共享状态在哪里？** — 堆内存 / 静态字段 / 外部存储 / 缓存？
2. **谁能写？** — 单线程 / 多线程 / 多进程 / 多节点？
3. **写入是否原子？** — CAS / 事务 / 分布式锁 / 无保护？
4. **是否有重复消费？** — 同一个消息/事件会被处理多次？
5. **是否有乱序？** — 消息顺序、事件顺序是否影响正确性？
6. **是否有并发覆盖？** — 后写覆盖先写且无版本号/乐观锁检测？
7. **锁使用是否正确？** — 锁粒度是否合理 / 是否误用分布式锁 / 是否存在死锁？

**禁止：**
- 用全方法 `synchronized` 解决并发问题（掩盖真正瓶颈）
- 在无保护的情况下把非线程安全对象暴露到多线程环境
- 不说明线程安全策略就声称"并发安全"

### 5. 动态控制病速查卡片

以下症状出现时，先查对应章节再改实现。

| 症状 | 可能的控制病 | 入口 |
|------|-------------|------|
| 瞬时尖峰被当成稳定趋势 | 采样周期过慢 / 别名 | `dynamic-control-diseases.md` §采样与观测新鲜度 |
| 阈值附近反复触发 | 缺滞回区间 / 缺去抖 | `dynamic-control-diseases.md` §去抖 / §滞回 |
| 恢复后立刻再次故障 | 退避不足 | `dynamic-control-diseases.md` §退避策略 |
| 调参与效果之间对不上 | 观测陈旧 / 传播时滞 | `dynamic-control-diseases.md` §观测新鲜度 |
| 熔断半开-关闭反复横跳 | anti-chatter 缺失 | `dynamic-control-diseases.md` §anti-chatter |
| 下游已挂但上游仍在重试 | anti-windup 缺失 | `dynamic-control-diseases.md` §anti-windup |
| 多个控制器同时改同一个 knob | 控制器冲突 | `dynamic-control-diseases.md` §控制器冲突 |
| 优化了旧瓶颈新主链被打坏 | 陈旧指标 / 观测盲区 | `dynamic-control-diseases.md` §陈旧指标 / §观测盲区 |

### 6. 反模式

| 反模式 | 说明 |
|--------|------|
| 凭感觉优化 | 没有 profiling baseline 就开始改代码 |
| 过度同步 | 全方法 `synchronized` 解决并发问题 |
| 盲目异步 | 不评估一致性代价就把同步改成异步 |
| 硬编码阈值 | timeout / retry 次数 / 熔断阈值写成经验常数（违反了机制优于策略） |
| 缓存无失效策略 | 引入缓存但不说什么时候失效、怎么失效 |
| 重试无退避 | 固定间隔连续重试放大下游故障 |

(完整决策准则见 `decision-principles.md`)
